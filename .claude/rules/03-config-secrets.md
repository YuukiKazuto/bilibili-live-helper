# 03 — 配置与密钥管理

> 上级文档：[../../CLAUDE.md](../../CLAUDE.md)。TTS 密钥读取见 [04-tts.md](04-tts.md)。

## 统一原则

所有密钥统一使用**项目配置文件**管理，涵盖：

- B站开放平台密钥（access_key / access_key_secret / app_id）
- 云端 TTS 密钥
- 后续新增的大模型 API 密钥等

### 主播身份码（id_code / 身份码）例外

主播身份码**不是**开发密钥，属于用户运行时凭证：

- **阶段 1**：由主播在前端 UI 界面填写；保存到本地用户偏好（类似存 JWT），下次打开应用时**自动填充**。
- **阶段 2**：改造为直播姬 H5 插件后，可直接在插件运行环境内获取身份码（官方插件容器提供），无需用户填写。
- 实现上：身份码随用户偏好配置持久化，与密钥配置分文件存放。

## 配置方案

- 格式可选 `.env` / `config.json` / `config.yaml` / `config.toml` 任一种（选定后在 `config/` 模块中统一封装加载器）。
- 使用 `load_dotenv` 加载配置到程序环境变量。
- 代码中**禁止硬编码任何密钥**；一律通过 `config/` 模块读取。

## 版本控制规范（红线）

- 仅带 `example` 后缀的示例配置文件（如 `.env.example`、`config.example.json`）可提交至 Git，示例文件中**只放占位符，不放真实值**。
- 真实密钥配置文件必须加入 `.gitignore`，**禁止提交密钥**。
- 每次提交前自查：`git status` 中不得出现未忽略的真实配置文件。

## 用户运行时配置

- 功能开关状态、金额阈值（默认 50 元，见 [02-features.md](02-features.md)）、TTS 模式选择等**用户偏好**与密钥分文件存放，用户配置可提交示例结构但不提交个人数据。
