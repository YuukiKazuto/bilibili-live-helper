# 07 — 桌面 UI 设计规范（PySide6）

> 上级文档：[../../CLAUDE.md](../../CLAUDE.md)。架构分层见 [01-architecture.md](01-architecture.md)，功能开关见 [02-features.md](02-features.md)。

## 框架选型（已定：PySide6）

**决策：PySide6（Qt for Python，Qt 官方绑定）。**

| 候选 | 结论 | 理由 |
|------|------|------|
| **PySide6** | ✅ 采用 | Qt 是企业级 GUI 事实标准，简历/岗位匹配度高；官方绑定 LGPL 许可，闭源/商用（阶段 2 订阅制）合法；信号槽、Model/View 等是可深聊的面试素材 |
| CustomTkinter | 淘汰 | 打包小但社区小、非企业主流 |
| Tkinter | 淘汰（保留为退路） | 标准库最稳，但界面与简历价值弱；CustomTkinter 同理 |
| PyQt6 | 不用 | 功能同 PySide6 但 GPL 许可，商用受限 |

**已接受的代价**：PyInstaller 打包 exe 约 100~200MB、冷启动慢几秒——换取生态与简历价值。

**退路**：UI 与逻辑按 [01-architecture.md](01-architecture.md) 严格隔离，若 PySide6 出现不可控问题，仅替换 UI 层，核心链路零改动。

## 互动消息实时显示 — 架构约束

**核心播报链路不动**，UI 只是 EventBus 的又一个订阅者：

```
platform → EventBus ─┬→ Broadcaster → 播报队列 → TTS   （现有链路不变）
                     └→ UI 互动消息面板                  （新增订阅者，只展示）
```

1. UI 面板**只展示不参与**：不做过滤、不进播报队列，显示与否不影响播报行为。
2. **跨线程投递**：asyncio 事件循环运行在后台线程，收到事件后通过 Qt 信号（signal）emit，槽函数（slot）在 UI 主线程渲染——禁止跨线程直接操作控件。
3. 所有事件（含未开启播报开关的事件）都显示在互动面板；面板内容与播报开关解耦。

## 打包

- PyInstaller 打包（`--windowed --onedir` 起步，onedir 启动快且便于排查；后续可做 onefile）。
- Qt 插件/资源由 PyInstaller hooks 自动收集，打包脚本入版本控制。
- 模型下载目录不能假设可写安装目录，规则见 [04-tts.md](04-tts.md)「模型存储目录」。
